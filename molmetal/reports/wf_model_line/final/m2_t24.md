## 2. What we learned from R15

The R15 CPU-Verify verdict (`wf_r15_cfm_cpu_verify/final.md`) is the load-bearing negative result:

> **decode_ratio = 0/8 at every checkpoint (100, 200, 500 steps) on BOTH CPU and GPU** — bit-exact. The bottleneck is the EGNN velocity field, NOT the device.

### Why all 4 attempts fail (consolidated diagnosis)

| Layer | Bottleneck | Evidence |
|---|---|---|
| **Atom coords** | EGNN outputs coord distribution that no decoder (heuristic or learned) can recover | 97.4% `disconnected_distance_graph` on Path-B GPU retrain (`wf_path_b_gpu_retrain/final.md` §1) |
| **Bond head** | `BondOrderHead.in_dim` mismatch was real (P0-F2) but NOT the ceiling | fix shipped, decode stays 0 |
| **Vocab mask** | P0-F3 fix recovers 88% wasted gradient on 12-vocab atom head | fix shipped, decode stays 0 |
| **Capacity** | hidden_dim=32 → 128 (P1.1) is 4× but still 10× under TargetDiff 1.2M params | shipped, decode stays 0 |
| **Pocket conditioning** | per-atom cross-attn (P1.3) shipped; hidden=0 zero-init in test broke test contract (not model bug — pre-existing) | shipped, decode stays 0 |
| **Decoder architecture** | Path B's soft distance mask + type compat + valence cap lifts 0/192 → 192/192 bond-bearing on SYNTHETIC clouds | smoke lift; real CFM output still 0/192 |

### Coord-quality wall, not capacity wall

R15 is decisive: **the EGNN produces an atom cloud whose pairwise distances do not match any chemistry decoder's prior.** No amount of decoder engineering (Path A/B/YuelBond) recovers from incoherent coords. The fix is upstream — either the EGNN architecture (EquiformerV2 / mHC fusion) or the training data (tmQM warm-start + curriculum).

## 3. 5 architectural paths forward (ranked by EV)

### Path 1: BondAwareDecoder + OT pair + better coord init (1 week, modest lift)

- **What:** Wrap DecoderRework around BondAwareDecoder at the **correct abstraction layer** (replace gumbel decode, not wrap it — `wf_path_b_gpu_retrain/final.md` §5.1) + RDKit `EmbedMolecule` with ETKDGv3 + MMFF94s coord init before decoder reads them + Optimal-Transport pair-loss (Tong 2024 NeurIPS) to match predicted atom-types to predicted coords.
- **Effort:** 1 week CPU + 6h GPU retrain at h=128.
- **Expected lift:** +5-15 pp decode (projected, not measured). Pushes to ~0.10-0.20 on 10000-step.
- **Why modest:** R15 says coord-quality wall, not bond-decoder wall. This fixes the wrap-ordering bug but doesn't touch the EGNN.
- **EV:** **MEDIUM** — ship if user has GPU budget, but do not block Q1 paper on it.

### Path 2: RxnFlow integration (from M2A) — borrow pretrained model (2 weeks)

- **What:** Per `wf_model_line/final/m2_rxnflow.md`, RxnFlow ships 109 Enamine REAL reaction templates + 13 uni + 58 bi-molecular HB templates + 1M ZINCFrag/Enamine blocks. Use RxnFlow's `reaction_templates/` as the **canonical typed-reduction set** that Lambda's click-rule set can reference (instead of hand-rolled `beta_reductions.py`). The 3D coord gap is bridged by keeping our `LipmanFlowMatchingAdapter` for coords + using RxnFlow for atom/bond priors.
- **Effort:** 2 weeks engineering; no GPU retrain needed (borrows pretrained model). Reaction-template adoption is CPU-only.
- **Expected lift:** Lambda diversity +5-15 pp (more templates → wider search space); no CFM decode change.
- **Why it matters:** This is the **architectural pivot** that dissolves the CFM-vs-Lambda dichotomy. Lambda becomes the reaction-template selector; CFM becomes the coord generator.
- **EV:** **HIGH** — independent of GPU; ships on CPU; directly strengthens §3.2 (5 click reactions).

### Path 3: YuelBond GNN decoder swap (already partially shipped)

- **What:** Wire `use_yuelbond=True` flag into `_generate_impl` (currently doesn't exist per R15 audit) + co-train YuelBond against same velocity field. R15 only ships the module + 5 wiring tests, NOT the live-stack integration.
- **Effort:** 1 day CPU wiring + 12-24h GPU co-retrain (YuelBond needs to see same EGNN output distribution).
- **Expected lift:** +5-15 pp decode (projected per R15; not measured because co-retrain never ran).
- **Why modest:** YuelBond is a better bond proposal head, but R15 evidence says the coord cloud is the wall, not the bond proposal. YuelBond helps if Path 1's coord-init ships first.
- **EV:** **MEDIUM** — sequenced AFTER Path 1's coord init.

### Path 4: Architecture rework — joint atom-type+bond-tensor (5-10 days, deferred)

- **What:** Replace `BondAwareDecoder` head with a joint transformer that predicts atom-type AND bond-tensor in one pass (RxnFlow's `env_context.py:68-83` does this for 2D; extend to 3D coord regression). Combined with EGNN spectral-norm + ε-norm regularizer (Neyshabur 2017 + Karczewski 2024 lit anchor).
- **Effort:** 5-10 days engineering + 24h GPU retrain. Tier-4 horizon.
- **Expected lift:** +10-25 pp decode (projected). Possible path to TargetDiff 30-65% parity.
- **Why deferred:** Requires sustained GPU budget (24h uninterrupted); only justified after Paths 1+3 verify that the coord-quality wall is the actual bottleneck, not a downstream artifact.
- **EV:** **HIGH if Paths 1+3 fail; ZERO if Paths 1+3 succeed** — option-value play.

### Path 5: Defer CFM entirely, ship Lambda-only (already done — paper de novo pivot)

- **What:** The paper already pivoted: §1+§2 rewritten for de novo typed-term MCTS framing (`wf_pivot_followup/MASTER.md` 2026-09-16). CFM moved from §3 to §7 future work. Path-(c) λ-only is Round-12/13 default. Round-13 100×3 sweep ships with Lambda-only.
- **Effort:** 0 — already done.
- **Why this is the answer:** Q1 paper submission deadline is binding. R15 evidence + R10 GPU retrain evidence + Path-B GPU retrain evidence all converge: **CFM is not lift-able in the Q1 window**. The honest framing is already in §6.1 (limitations) + §7.1 (future work).
