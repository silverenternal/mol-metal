## 2 — WHY the re-sync is to 129/131 and NOT to 153

The brief's proposed count (153) is the count the tree would have if the 24
unregistered Wf-432-A1 gates were wired in.  They are NOT wired in — that is
another branch's scope, and it may never ship.  The stale pins are a defect
**in their own right**: they have been RED since before 2026-11-01 and they
fail for a reason unrelated to the code they claim to guard.  So they are
re-synced to the count that is TRUE today (129/131, MEASURED by live import),
independently of whether the 24 gates are ever wired in.  If they are wired
in later, the count moves to 153 and a SECOND re-sync is required — that is
correct and expected; a stale pin that is re-synced to a speculative number
is worse than a stale pin, because it goes RED again the moment the
speculation does not happen.

The re-sync is the MINIMAL edit: the numeric literal changes, and a **dated**
comment is added that names the superseded value and the wave that missed
it (AGENTS.md §5.5 rule 6 — append-only + dated; the superseded rendering of
prose is preserved verbatim, never silently edited, never deleted).

## 4 — `test_wf350c1_gpu_env_probe.py` — 2 of its 3 failures are NOT count pins

The 3 failures MEASURED at 2026-11-01 12:19 were:

1. `assert result.status == "PASS"` — the `p1_gpu_env_probe` gate returns

2. `assert result.status in ("PASS", "FAIL")` — SKIP is not in the allowed set.
3. the count pin `EXPECTED_GATE_COUNTS["all"] == 94` — the Wf-350-C1 ship
   target, vs the live 129.

(1) and (2) are a **CPU-lock artefact**, not a count pin, and are **not
fixable by any re-sync**: the gate SKIPs when — and only when — the session
hides the GPUs from torch (`CUDA_VISIBLE_DEVICES` present and blank: the
repo's standing CPU lock, applied at IMPORT time by BOTH the repo-root
`conftest.py` and `molmetal/tests/conftest.py`).  In such a session the
probe's torch half cannot see a GPU by construction; `nvidia-smi` is
unaffected by the lock, so the gate still reports the host facts it did
measure.  A SKIP is neither a FAIL nor a false PASS, and asserting PASS there
would be a false green.

MEASURED at 2026-11-01 12:24: **another wave (Wf-A170) repaired this file
concurrently** — its sha256 moved `d07651a544f9…` (the Wf-A169 backup taken
