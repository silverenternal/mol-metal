## A1 spec — learned bond-order head (NEW module `molmetal/models/bond_head.py`)

**Goal:** replace the fixed distance-connectivity decoder with a *learned* per-edge bond head that takes EGNN pair features and emits (bond_exists ∈ {0,1}, bond_order ∈ {1,2,3,aromatic}) per ordered pair; consume from `EGNNVelocityField.forward` so the same hidden state `h` that drives `atom_head` and `vel_head` also drives the bond prediction; train on tmQM-derived (pos, atom_types, true_bonds) pairs using a hybrid CE + BCE loss with class weighting so single / double / aromatic are balanced.

**Module surface (NEW, no edits to existing files):**
- `class LearnedBondHead(nn.Module)` in `molmetal/models/bond_head.py`.
- `__init__(hidden_dim: int, n_layers: int = 2, n_bond_classes: int = 4)` — 4 classes = {no-bond, single, double, aromatic}; default `4` matches RDKit's `Chem.BondType` collapsed set (SINGLE=1, DOUBLE=2, TRIPLE=3, AROMATIC=12 → 4-way classification with no-bond as the 0-th class).
- `forward(h: Tensor, edge_index: LongTensor, edge_mask: Optional[BoolTensor] = None) -> (B, E, n_bond_classes) logits` — consumes the same per-node `h` and `edge_index` produced inside `EGNNVelocityField` (currently computed in `molmetal/adapters/flow_matching_lipman/__init__.py:951-960`); symmetric pair features are constructed by concatenating `h_i ⊕ h_j ⊕ rel_pos_norm` and projected through a small MLP (`_MaybeFusedSiLUMLP`-compatible so the `triton_kernels.fused_silu_mlp` path lights up on the same shapes as the encoder's update_mlp).
- `class BondHeadLoss(nn.Module)` — `forward(logits, target_bond_classes, edge_mask) -> scalar`. CE over 4 classes, masked by `edge_mask`, class weights = inverse-frequency from tmQM. Returns a tensor that callers add to the CFM+atom loss with a tunable weight (initial spec: `bond_loss_weight = 1.0`, matching `atom_loss_weight`).
- `class BondHeadDecoder` — greedy argmax with RDKit sanitisation: emit `Chem.RWMol`, add atoms, set per-edge bond types using RDKit `Chem.BondType.{SINGLE,DOUBLE,AROMATIC}` mapping, then `Chem.SanitizeMol` → return `(mol | None, status_str)` reusing the same status vocabulary as `decode_distance_graph` (`decoded_distance_graph`, `disconnected_distance_graph`, `radical_graph`, `connectivity_or_valence_failure:<ExcName>`) so the harness can swap decoders without changing `cell['samples']` / `decode_status_counts` schema. Crucially, this decoder handles its own atom-block validation so the bond head need not model Z; the vocabulary problem is A1's orthogonal sibling A2.

**Wiring inside `EGNNVelocityField.forward` (NOT touched by this audit; spec only):** after the existing EGNN loop (lines 951-960), expose `last_h = h`, `last_edge_index = edge_index`, `last_edge_mask = edge_mask` as instance attributes (same pattern as `self._last_dative_flag` on line 914). Then a `self.bond_head = LearnedBondHead(hidden_dim)` (added in `__init__` after `self.atom_head`) consumes those cached tensors and emits logits. During training the `bond_loss` is added to the existing `loss = cfm_loss + atom_loss_weight * atom_loss` (line 1410) as `+ bond_loss_weight * bond_loss`; during sampling the harness calls `adapter.bond_head.decode(h, edge_index, edge_mask)` to materialise an RDKit mol per sample instead of `decode_distance_graph`. Wireup is opt-in via `LipmanFlowMatchingAdapter.__init__(..., use_bond_head: bool = False, bond_loss_weight: float = 1.0)` so the legacy path is **bit-exact unchanged** when `use_bond_head=False` — matching the "do not modify existing decoder/harness" constraint.

**Train data:** reuse the tmQM-derived `(pos, atom_types, true_bonds)` tensors already cached for the F2 pretrain (see `molmetal/reports/f2_tmqm_pretrain.md`, `molmetal/checkpoints/dmpnn_tmqm_pretrained.pt`); `BondHeadLoss` consumes a `target_bond_classes: LongTensor[B, E]` produced by an RDKit-side pre-computation that maps each tmQM bond into one of {no-bond, single, double, aromatic}. Pretrain the bond head on tmQM first (per-edge CE; expect Wiberg-BO MAE ≤ 0.20 from the F2 encoder), then co-train with the CFM+atom loss on CrossDocked for the Round-12 / Round-13 sweep.

**Reuse / `molmetal/adapters/egnn_rocm.py`:** the bond head's pair-feature MLP is shape-compatible with `_MaybeFusedSiLUMLP` (existing local helper at `molmetal/adapters/flow_matching_lipman/__init__.py:59-89`) so the Triton-fused SiLU+matmul path lights up when the hidden dims match. The pair feature is `h_i ⊕ h_j ⊕ ||r_ij||` with `r_ij = x_j - x_i`; edge index and edge mask come from the existing `_make_dummy_edge_index` and `node_mask`-derived `edge_mask` used elsewhere in the adapter.

## A2 spec — atom-vocabulary mask (in-place patch inside `LipmanFlowMatchingAdapter._generate_impl`)

**Goal:** at the exact softmax site (`molmetal/adapters/flow_matching_lipman/__init__.py:1650`), mask `atom_logits[..., z] = float("-inf")` for every `z` that is NOT in the atom vocabulary used by the chosen training set, so the categorical draw can never sample Z ∉ vocab. Initial vocab (matching `r10_cfg_real_crossdocked.py:42` decoder `allowed_atoms=(6,7,8,9)` and the F2 tmQM cross-docked training set) = `{6, 7, 8, 9}` for the light-atom path; the full chemistry-aware vocab (matching the brief in `WF-1 CFG architectural fix ultracode` task #353 description) = `{1, 6, 7, 8, 9, 15, 16, 17, 34, 35, 53, 78}` (H, C, N, O, F, P, S, Cl, Br, I, Pt) — the metal set is initialised from `molmetal/molmetal_lam/priors/metal_geometry.py:DEFAULT_METAL_GEOMETRY` keys (78=SP, 46=SP, 29=TD, 30=TD, 26=OCT, 44=OCT, 77=OCT, 45=OCT, 25=TBP → {78, 46, 29, 30, 26, 44, 77, 45, 25}) augmented with the canonical donor / halogen set {1, 6, 7, 8, 9, 15, 16, 17, 34, 35, 53}; the union yields {1, 6, 7, 8, 9, 15, 16, 17, 25, 26, 29, 30, 34, 35, 44, 45, 46, 53, 77, 78} = 20 classes. A2 lives behind a `LipmanFlowMatchingAdapter.__init__(..., atom_vocab: Optional[Sequence[int]] = None)` knob that defaults to `None` (legacy bit-exact path, mask is a no-op) and is wired through `setup()` and `_generate_impl`.

**Critical preservation guarantees (no behaviour change when off):**
1. The mask is applied **after** the CFG interpolation at line 1636-1639 (so CFG still sees the un-masked logit tensor; the mask is a post-CFG constraint on what `multinomial` is allowed to draw). The mask slot is inserted between line 1649 (`atom_logits[..., 0] = float("-inf")`) and line 1650 (`atom_probs = F.softmax(atom_logits, dim=-1)`) as the new line `if self._atom_vocab_mask is not None: atom_logits[..., self._atom_vocab_mask] = float("-inf")`.
2. Z=0 (the padding channel) stays `-inf` regardless — line 1649 is preserved as the first mask slot.
3. The mask is a **boolean** numpy/torch index (shape `(max_atomic_number,)`, `True` = banned). The class is built once at `setup()` from the union-of-keys of `DEFAULT_METAL_GEOMETRY` plus the explicit donor/halogen set; cached on `self._atom_vocab_mask: torch.BoolTensor`.
4. **Training path is unchanged**: the existing `F.cross_entropy(atom_logits, atom_types)` at line 1402 will silently logit-suppress vocab-excluded classes without changing the bit-exact training trajectory for in-vocab atoms (excluded classes get -inf logit → 0 probability → 0 contribution to the loss). For atoms whose ground-truth Z is outside the chosen vocab (none in CrossDocked-{C,N,O,F}; some in tmQM-Pt/Pd/Ir), we add a vocab-coverage precheck that emits a one-shot warning and skips those atoms (rather than crashing with `RuntimeError: logit -inf at true class`). **This is the only training-path edit and it's opt-in via the same `atom_vocab` knob.**
5. Decode path (`r10_cfg_real_crossdocked.py:42-75`) sees the masked atom list as input — `decode_distance_graph`'s own early-rejection `atom_outside_training_vocabulary` becomes dead-code on the masked path (no Z ∉ vocab ever reaches it); the decoder's `allowed_atoms` should be widened to match the new vocab (the brief's `--seeds` extension is the natural place to pass `--atom-vocab 1,6,7,8,9,...` and pipe it into both the adapter and the decoder).

**Reuse / `molmetal/molmetal_lam/priors/metal_geometry.py:DEFAULT_METAL_GEOMETRY`:** the A2 vocab derivation reads `list(DEFAULT_METAL_GEOMETRY.keys())` (the canonical Z→geometry map at lines 364-374) and unions it with the donor/halogen set. No copy of the dict; the import is the single source of truth so adding Pt-class centres to the prior automatically widens the atom-vocab (e.g. adding Os=76 to `DEFAULT_METAL_GEOMETRY` immediately enables Os generation under the mask).
