## 5. Root cause analysis

The blocker is **environmental, not source**:

1. **Disk-quota exceeded** on `/var/lib/texmf/fonts/map/pdftex/updmap/`
   during pdflatex's font-map cache flush.
2. The mount is also unreadable for some metadata operations (cp, stat, df
   all return non-zero) — likely the quota is enforced at the VFS layer
   rather than per-file.
3. No userland workaround is possible without root/sudo (regenerating
   pdflatex format with a redirected TEXMFVAR requires writing to
   `/var/lib/texmf/web2c/`).

The Phase 2 source-fix is solid (verified by Phase 3 pdflatex reaching §1.1).
A successful build requires clearing the disk quota on the build host —
out of scope for this workflow.
