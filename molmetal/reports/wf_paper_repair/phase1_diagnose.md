### 2.2 Why `paper/sections/01_intro.tex' not found`

`main.tex` lines 173-201 use the include pattern

```
\input{paper/sections/01_intro}
\input{paper/sections/02_related}
\input{paper/sections/03_method}
\input{paper/sections/04_evaluation}
\input{paper/sections/05_ablation}

```

These **only resolve correctly when `pdflatex main.tex` is invoked from the
project root** (`/home/hugo/codes/try_triton_on_rocm/`), where `./paper/sections/01_intro.tex`
exists. If `pdflatex` is invoked from inside `/home/hugo/codes/try_triton_on_rocm/paper/`
(which is how every prior compile attempt in memory says it was run, e.g.
"cd paper && pdflatex main"), then TeX looks for `./paper/sections/01_intro.tex`
relative to the working dir, i.e. `paper/paper/sections/01_intro.tex`, which
does not exist.

A second piece of evidence: the bibtex run recorded in `main.blg` shows

```
I couldn't open database file paper/refs.bib
---line 369 of file main.aux
 : \bibdata{paper/refs
 :                    }
```

which is exactly the same bug: `bibtex main` was run from inside `paper/` and
BibTeX looked for `paper/refs.bib` in the working directory. The .aux was
generated with `\bibdata{paper/refs}` because pdflatex was run from the project
root, then bibtex was run from `paper/` and the path no longer matches.
