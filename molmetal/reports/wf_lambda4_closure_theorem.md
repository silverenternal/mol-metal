## 1. Spec

The WF-Lambda-4 task ships a formal closure theorem for the
constructive synthesis space generated by the 5 click combinators
(CuAAC, SPAAC, Thiol-ene, Suzuki-Miyaura, Amide coupling).  The
theorem states:

> **Closure Theorem.** Given a starting scaffold `S` and a fixed
> reaction budget `d`, the set of `MoleculeClosedTerm` instances
> reachable via up to `d` applications of the 5 click combinators
> is **the constructive synthesis space** — every term in this
> space has a β-reduction witness path back to the click application
> sequence.

### 1.1 Formal statement

For every closed term $T_0 \in \mathrm{Closed}$ and every subset
$\mathcal{R}' \subseteq \mathcal{R} = \{\mathrm{CuAAC},
\mathrm{SPAAC}, \mathrm{ThiolEne}, \mathrm{Suzuki},
\mathrm{AmideCoupling}\}$, the reachable set

$$\mathcal{P}(T_0, \mathcal{R}', d) = \{ T : T_0 \rightarrow_{\mathcal{R}'}^{\le d} T \}$$

satisfies:

- **(i) Valence-BNF well-typedness**: every $T$ is RDKit-sanitisable
  and valence-saturated.
- **(ii) β-reduction witness**: every $T \ne T_0$ has a finite
  witness path of rule applications back to $T_0$.
- **(iii) Complexity**: the BFS terminates in
  $O(|\mathcal{R}'|^d \cdot C)$ calls.

### 1.2 Honest framing

The closure theorem is proved **operationally**: we enumerate the
reachable set via BFS and check the well-formedness of each term.
This is **sound** (every enumerated term is reachable) but
**incomplete** (we cannot prove there is no term outside our
enumeration that violates the closure property).  Soundness is what
is required for the constructive synthesis guarantee — the search
cannot propose a term outside the reachable set.

## 2. Algorithm (ProductiveSpace.reachable_terms)

```
reachable_terms(start_term, click_rules, max_depth, max_products):
    visited := { canonical(start_term) -> (start_term, []) }
    frontier := deque([(0, start_term, [])])
    yield start_term
    while frontier:
        depth, term, witness := frontier.popleft()
        if depth >= max_depth: continue
        for rule in click_rules:
            for (partner_term, _) in visited.values():
                if canonical(partner_term) == canonical(term): continue
                products := safe_reduce(rule, (term, partner_term))
                for product in products:
                    key := canonical(product)
                    if key in visited: continue
                    if |visited| >= max_products: warn + return
                    new_witness := witness + [(rule.name, [k_a, k_b, key])]
                    visited[key] := (product, new_witness)
                    frontier.append((depth+1, product, new_witness))
                    yield product
```

### 2.1 BFS invariants

1. **Canonical-keyed dedup**: every α-equivalence class is emitted
   exactly once (canonical SMILES from `term.canonical_smiles()`).
2. **Depth bound**: no term with witness length > max_depth is
   emitted.
3. **Witness attached**: every emitted term carries the private
   `_closure_witness` attribute (a list of
   `(rule_name, [parent_a_key, parent_b_key, product_key])` triples).

### 2.2 Algorithm complexity

- **Time**: $O(d \cdot |\mathcal{R}'| \cdot N^2 \cdot C)$ where $N$
  is the reachable set size and $C \approx 50\,\mu s$ per
  `rule.reduce` call.
- **Space**: $O(N)$ for the visited dict + $O(d \cdot N)$ for the
  frontier deque.
- **Worst-case**: $O(|\mathcal{R}'|^d \cdot C)$ rule applications.

## 4. PROJECTED scaling

For the n_plus_ultra regime (220-tile ChEMBL/ZINC pool + 5 click
rules at depth 4):

- **Branching factor**: ≤ 5 click rules × ~50 partner candidates per
  frontier node = ≤ 250 expansion candidates per node.
- **Frontier size at depth 4**: worst-case 250⁴ ≈ 4×10⁹ raw
  candidates, capped by α-equivalence dedup to ≲ 10⁴ distinct
  products.
- **Wall-time on CPU**: PROJECTED ≤ 10 minutes
  ($\sim 625$ rule applications at $\le 50\,\mu s$/call +
  RDKit sanitisation overhead for $\sim 10^4$ products
  at $\le 30$ ms/sanitisation $\approx 5$ min).

### 4.1 PROJECTED GPU acceleration

Offloading the BFS inner loop to a Triton kernel over the partner
candidates is PROJECTED to yield a 10-50× speedup on the
RX 7800 XT (gfx1101, wave64) for depth ≥ 4, since the (rule, pair)
contraction is embarrassingly parallel.
