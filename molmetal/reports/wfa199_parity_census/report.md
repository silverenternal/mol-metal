## 2. Key-name pattern set (documented)

- **R1 supersession token** -- the key name contains one of these tokens (case-insensitive): `demote`, `demoted`, `demotion`, `demotions`, `deprecated`, `historical`, `historically`, `legacy`, `obsolete`, `retract`, `retracted`, `retraction`, `supersede`, `superseded`, `supersedes`, `supersession`, `supersessions`
- **R2 closed + date** -- token 'closed' AND a date-shaped token (YYYY-MM-DD / YYYY_MM_DD)
- **R3 date + supersession word** -- date-shaped token AND a supersession/demotion word as a SUBSTRING (supersed|demot|retract|historic|obsolet|deprecat|legacy|closed)
- **no-descent rule** -- a matched record's children are payload, not separate records; the walk does not descend into a matched key
- **literal hit** -- the key name is an exact Python string constant in the producer (ast.Constant); prose mentions do not count
- **dynamic hit** -- every alphabetic token of the key occurs in the producer source and the digit runs can be matched with \d+ inside one statement, so the producer could build the name at run time
