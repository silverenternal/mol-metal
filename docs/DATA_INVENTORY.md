## 1. What each model trains on

### 1.1 Predictive: D-MPNN metal activity

Cohort: `build_paper_cohort(MetalCytoToxDB, metal)`, then
`collapse_duplicates(tie -> active)`. A row is active when
`IC50_Dark_value < 10 µM`.

| Metal | Funnel rows | Unique SMILES | Active | Inactive |
|---|---:|---:|---:|---:|
| Ru | 15,799 | 4,793 | 1,557 | 3,236 |
| Ir | 3,674 | 1,281 | 655 | 626 |
| Rh | 951 | 334 | 170 | 164 |
| Os | 966 | 333 | 155 | 178 |
| Re | 666 | 250 | 75 | 175 |
| **Total (per-metal sum)** | | **6,991** | | |

A SMILES can appear under more than one metal, so the per-metal sum is
not a count of distinct molecules. Evaluation uses
`StratifiedKFold(n_splits=5)` with seeds `[42,43,44,49,123]` and no
fixed holdout: every molecule is tested in one fold.

**Leakage.** Raw SMILES are canonical and unique within each metal cohort (0
multi-string molecules, 0 exact duplicates after collapse), so no molecule
appears in both train and test: 0.00 % of test rows under both the random and
the DOI-grouped protocol. The random CV is in-domain by scaffold, with
74.8-85.7 % of test rows sharing a Bemis-Murcko scaffold with train (45.7-64.2
% under DOI-grouped 10-fold). Report it as a random-split AUC, not as a
scaffold-generalisation estimate. Source: `docs/DATA_LEAKAGE_AUDIT.md`.

### 1.2 Generative: CFM 5-metal

- Rows 26,632; unique SMILES 6,743; cell lines 744
- Metals: Ru 18,987, Ir 4,546, Rh 1,118, Os 1,113, Re 868
- In-file scaffold split: train 18,137, test 5,736, val 2,759
- Activity: 0 17,471, 1 9,161

The CFM is generative, so there is no held-out property test set.
Quality is measured by decoding validation clouds (validity, ring
profile, novelty, docking), not by a train/test AUC.

**Leakage.** The in-file `scaffold_id` is stereo-aware and covers the whole
complex, counterions included. It is disjoint across train/val/test (0
shared), and no SMILES carries more than one split label. On a desalted,
stereo-blind ligand scaffold, 222 scaffolds are shared between train and test
(73.7 % of test rows) and 131 between train and val (79.6 % of val rows).
Removing stereo alone leaves 30 shared scaffolds (4.2 % of test rows), so most
of the overlap comes from counterion and solvent fragments. The split is not a
ligand-scaffold OOD split.

**Second data path: tmQM geometry.** CFM configs that train the velocity field
on 3-D clouds read `.data/molmetal/tmQM` instead of a CSV: 33,429 six-metal
complexes with geometry, Wiberg bond orders and NBO charges on every row (see
`tmqm_corpus_6metal` in section 2). The corpus is complete. Two protocol
values affect any generation metric quoted from it: the scaffold split is
87.7/6.2/6.2 % of rows, and the default 192-cloud val cohort is Pt 19 / Ru 93
against a corpus that is Pt 24.8 / Ru 29.3. Source:
`metrics/by_metric/tmqm_cfm_data_audit.json`.

### 1.4 Controls

- NCI-60 precious-metal panel: 7,823 rows, 5,207 unique SMILES, 9 cell lines.
  The default split (`scaffold_coverage_70_10_20`, since 2026-10-21) gives

  5,207 canonical molecules appear in the 5-metal pool and 5,183 in CFM. The
  3,645/521/1,041 figure comes from the pre-BLK-PA12 splitter and no longer
  reproduces.
- MoleculeNet (bace, bbbp, clintox, hiv): scaffold 70/10/20, 5 seeds. The
  split key is stereo-aware. At the stereo-blind level at most 0 scaffolds are
  shared between train and test (0.0 % of test rows, bace); desalting adds a
  counterion component of up to 52 scaffolds (hiv), with a row-level maximum
  of 35.3 % (bbbp). Canonical molecule overlap is 0.
- DrugOOD lbap: 266,522 rows with iid/ood train/val/test as a column. Used as
  the OOD control, not as a headline result. Train vs ood_test shares 0
  canonical molecules and 0 scaffold IDs; train vs iid_test shares scaffold
  IDs by design.

## 3. Notes per dataset

- **`metalcytotox_raw`** (ACTIVE): Raw Krasnov corpus. Predictive cohorts are
  derived from this by `build_paper_cohort()` and
  `collapse_duplicates(tie -> active)`.
- **`cfm_5metal_v3`** (ACTIVE): Canonical CFM cohort
  (`configs/cfm_5metal_default.yaml`). The in-file `split` column is
  stereo-aware and covers the whole complex; it is not a desalted
  ligand-scaffold split (see `docs/DATA_LEAKAGE_AUDIT.md`).
- **`cfm_5metal_v4`** (ACTIVE): Same rows as v3, plus lowercase
  `smiles`/`metal` aliases and a `source` column. Ten configs read it; kept
  because both are wired. Same split caveat as v3.
- **`cfm_5metal_v5`** (UNUSED): Deduplicated rebuild (24,483 rows) with a
  desalted stereo-blind ligand-scaffold split: 17,138/2,448/4,897, 0 shared
  scaffolds and 0 shared canonical SMILES across every split pair, all five
  metals in all three splits. Built by `wf_a52_rebuild_cfm_split.py`. No
  training config reads it yet. Its test split has one consumer:
  `wf_a53_eval_cfm_test_split.py` scores a checkpoint on `split='test'`
  read-only (4,888 of 4,897 rows embed; 4,888 carry bond truth).
- **`cfm_5metal_v2`** (SUPERSEDED): Same 26,632 rows as v3, differing only in
  column naming (lowercase `smiles`/`metal` against `SMILES_Ligands`/`Metal`).
  Use v3.
- **`cfm_5metal_v1`** (SUPERSEDED): Pre-v2 cohort; only legacy configs.
- **`pt_biodata_all`** (ACTIVE): 17,735 real MB-Finder Pt IC50 rows, all
  SMILES-joined (Wf-A46/47/48/49). No split column; 3,668 duplicate
  `(code, cell)` rows and 987 exact duplicate measurements; 296 unique SMILES
  fail RDKit parsing.
- **`pt_biodata_raw`** (ACTIVE): All-metal harvest summary: 485 cell lines /
  30,185 rows.
- **`pt_4cell_synthetic`** (DO-NOT-TRAIN): Synthetic pIC50 (its meta file says
  'synthetic IC50 labels for pipeline test'). Its ~0.50 AUC is a null test,
  not a measurement.
- **`pt_real_label_pool`** (SUPERSEDED): Real labels, but only 1 of 2,053 rows
  carries SMILES; superseded by `pt_biodata_all`.
- **`pt_4cell_real`** (ACTIVE): Real structures and real IC50 labels for the
  four PlatinAI cell lines, built from the 2026-10-19 MB-Finder harvest by
  `build_platinai_4cell_real_cohort.py`. 1,966 compounds and 3,144 unique
  (compound, cell) pairs from 4,370 raw biodata rows (A549 871, A2780 860,
  A2780cis 600, MCF-7 813); 953 compounds cover at least two cells and 56
  cover all four. Units are µM, taken from the Rusanov 2025 SI figure
  captions; pIC50 = 6 - log10(IC50_uM). The file holds 1,935 unique SMILES
  rather than 1,966, because 28 SMILES appear under 2-3 compound codes (59
  rows) with per-cell labels up to 1.45 log units apart. The split groups by
  scaffold, so those duplicates cannot cross train/test, but the compound
  count overstates chemical diversity by 1.6 %.
- **`pt_4cell_real_trainer`** (ACTIVE): The same 1,966 compounds projected
  into the schema `load_platinai_4cell_split_table` accepts (`SMILES_Ligands`,
  `pIC50_{a549,a2780,a2780cis,mcf7}`, `metal=Pt`). No measurement is added,
  dropped or imputed. A compound with no IC50 for a cell line has an empty
  cell, which the loader turns into NaN and masks out of the loss. The file
  exists so the D-MPNN trainer can read real labels without a hand-edited CSV.

  `ablation_runner.py`; not a labelled cohort.
- **`tmqm_dblock`** (ACTIVE): 5,000 d-block complexes with geometry. A small
  subset, not the CFM corpus, which is `tmqm_corpus_6metal` below. The
  tmQM-pretrained encoder
  (`models/tmqm_pretrained/tmqm_pretrained_encoder.pt`) is loaded by the
  current CFM configs (`use_tmqm_init: true`; 47/51 parameters transfer, 0

  see `TODO/risks.md` R6.
- **`tmqm_corpus_6metal`** (ACTIVE): The tmQM corpus the CFM geometry path
  trains on. The file holds 108,541 complexes over the whole d block; the CFM
  cohorts are the six-metal subset, 33,429 complexes over Pt, Ru, Ir, Rh, Os
  and Re. Every one of those carries all three shards a cloud needs (geometry,
  Wiberg bond orders, NBO charges): 33,429/33,429 on each. No duplicate CSD
  codes, no non-finite coordinates, one metal atom per complex, and the
  `metal` column agrees with that atom in 33,429/33,429 rows. 2,277 rows (6.8

  protocol values, not corpus defects: the scaffold split is 87.7/6.2/6.2 % of
  rows rather than 80/10/10 (fractions are budgeted in scaffold counts, so
  `tmqm_val_frac` has no effect on that branch), and the default `n_val=192`
  cohort with `tmqm_min_per_metal=0` is Pt 19 / Ru 93 against a corpus that is
  Pt 24.8 / Ru 29.3. Source: `metrics/by_metric/tmqm_cfm_data_audit.json`.
- **`crossdocked100`** (ACTIVE): 100-pocket docking manifest for the pocket

- **`rusanov_s5_ece`** (REFERENCE): Published ECE values; compared against,

- **`rusanov_s7_pt_wet_lab`** (REFERENCE): Published Pt-1..19 wet-lab panel;

## 5. Known gaps

Open:

- No model has been retrained on the NCI-60 coverage split. The default moved
  on 2026-10-21 (see Closed below). Until a run lands, the only 9-cell number
  on disk (0.7294) was measured on the legacy protocol and is not comparable
  to anything measured on the new test set, which is 1,532 rows against 343.
  Source: `metrics/by_metric/nci60_split_coverage_audit.json`; risk
  `TODO/risks.md` R11.
- tmQM's val cohort is not metal-balanced. `n_val` defaults to 192 and
  `tmqm_min_per_metal` to 0, so the cohort behind every generation metric is a
  192-of-960 reservoir window: at seed 0 it is Pt 19 / Ru 93 against a corpus
  that is Pt 24.8 / Ru 29.3. `tmqm_min_per_metal: 20` gives Pt 46 / Ru 52 and
  forces a full 2,061-candidate scan. Source:
  `metrics/by_metric/tmqm_cfm_data_audit.json`.
- CFM v3/v4 `scaffold_id` is a whole-complex, stereo-aware key, so 73.7 % of
  test rows share a desalted scaffold with train. `cfm_5metal_v5` fixes this
  (0 shared scaffolds), but no checkpoint has been trained from it; see
  section 3.
- `pt_biodata_all` is a pool, not a partition: 17,735 rows, 3,668 duplicate
  `(compound_code, cell_line)` rows, 987 exact duplicate measurements, and 296
  unique SMILES that fail RDKit parsing. The 4-cell cohort filters and
  median-collapses these (counted in its `.meta.json`); the raw pool is
  unchanged.
