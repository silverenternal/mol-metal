## §1 Five standing project rules

These rules apply to **every** agent action in this repo. Violations are honest-negatives.

1. **MEASURED-vs-PROJECTED tag discipline** (`party-twenty-spirit` §3.5). Every numeric value in
   any agent output MUST trace to a JSON / report path on disk. PROJECTED vs MEASURED tag is
   required. Zero tolerance for fabricated / aspirational numbers in main results.
2. **Standing GPU authorization (2026-09-29 user grant)**. User has granted GENERAL GPU
   authorization going forward — **"显存够就放心大胆用"** (use freely as long as VRAM is enough).
   No per-launch user OK required. Constraints:
   - **VRAM budget check first**: `nvidia-smi` shows free VRAM (e.g. RTX PRO 6000 Blackwell
     98GB or RTX 5090 32GB); abort if OOM risk.
   - **Hyperparameters via config files**: reference peer papers in the same domain; encode
     in `--batch-size`, `--lr`, `--hidden`, `--depth` config rather than guessing.
   - **Pre-flight PASS**: still required (`pre_flight_check.py`).
   - **Dry-run defaults**: still default for scripts.
3. **No paper work without authorization** (TODO-84 active). Zero touches to `paper/*` unless
   user explicitly OKs.
4. **Pre-flight v2 25/25 PASS gate** (TODO-207). Any agent launching a retrain / panel /
   ablation MUST run `pre_flight_check.py` first. STALE flag (24 hr) blocks PASS.
5. **Honest-negative framing** (`party-twenty-spirit` §3.5). When a metric is BELOW field-avg
   or BLOCKED on external dependency, declare it as honest-negative — never paraphrase as
   "achievable" / "promising" without PROJECTED tag + wall budget.

### §5.11 YAML-only launch (no CLI hyperparameters) — INLINE

**User directive 2026-10-09, verbatim: "以后要求能且只能用yaml配置启动训练和推理，
no cli参数"** — training and inference launch from the YAML config. Every
hyperparameter is declared in `configs/*.yaml`; a launch wrapper sets up the
environment, detaches, and redirects, nothing more.

A wrapper may pass **only** `--config`, `--out-dir`, `--ckpt-dir`, `--help` — flags
that select *which run*, never *what to train*. `--extra-flags` is **REFUSED** by
`scripts/start.sh`, not deprecated.

| Surface | Role |
|---|---|
| `scripts/_yaml_only_gate.py` | Fails the launch if any wrapper smuggles a trainer flag |
| `scripts/_config_binding_gate.py` | Fails if any config key resolves to no dest of its own `entry.script` parser |
| `pre_flight_check.py` | `p3_yaml_only_launch_check` + `p3_config_trainer_binding_check` (launch pipeline) |
| `molmetal/tests/test_wf_yaml_only_gate.py` + `test_wf_config_binding_gate.py` | 35 regression tests over the gates themselves |
| `molmetal/scripts/wfA2_config_loader.py` | Resolves YAML leaves → trainer dests; holds `DECLARED_INERT_PATHS` |

**Why:** before this rule, 54 hyperparameters across 6 wrappers were set on command
lines instead of configs. That is not tidiness — it is how `use_fm_objective` came
to be silently absent from 5 of 7 CFM configs while the EGNN velocity field was
built and trained anyway: `fm_term` was an exact zero, so the field's only gradient
was a Wasserstein geometry anchor, while `method: rk4` still integrated it as an
ODE velocity function. A knob that lives only in a shell script is a knob nobody
audits.

**Three dispositions for a key that resolves to no dest** — the middle one is the
point: a key either reaches a dest, has a *verified* non-trainer consumer
(`_NON_TRAINER_PATHS`), or is `DECLARED_INERT_PATHS` — documented intent with
**zero consumers repo-wide** (split-protocol prose, sweep structure, MEASURED
baselines). Inert keys are printed on **every** run and never fatal. Anything else
fails the launch.

**How to apply:** to add a hyperparameter, add it to the YAML and verify the
round-trip (`parse_args(["--config", cfg])` returns the non-default value). To add
a new trainer that must be config-driven, wire `apply_yaml_overrides` into its
`_parse_args` — and per §5.7, smoke it end-to-end before calling it shipped.
`entry.command_template` may use `{placeholder}` values (start.sh fills those from
the same YAML); a **literal** value or bare switch there is a violation.

**⚠️ LIST-valued flags must be YAML lists.** A flag declared `nargs="+"` (e.g.
`--metals`) arrives from the CLI as a list of tokens. Writing `metals: Ru Ir Os Re`
in the YAML delivers ONE string instead — the trainer then looks for a metal
literally named `"Ru Ir Os Re"`, matches no rows, and every fold yields an empty
test set → `test_auc = nan` for every seed. **Both §5.11 gates pass on this**:
the config-binding gate checks the key resolves to a dest (it does), and the §5.1
hyperparam gate checks four scalars (this is not one of them). Verified on
2026-10-09 by losing a full 4-fold × 5-seed run to it. So verify the round-trip by
**type**, not just by value: `isinstance(args.metals, list)`, not `args.metals !=
default`.

**Precedence is now decided by the real signal, not a proxy.** `apply_yaml_overrides`
used `cur == dft` (current value equals the argparse default) to mean "the caller did
not pass this flag". That conflated *explicitly passing the default value* with *passing
nothing*, so the YAML silently overrode an explicit choice. It now probes the actual
argv (`_supplied_dests`), guarded so a caller passing nothing behaves exactly as before.
Precedence, in order: **explicit CLI flag > YAML > argparse default**, and for
list-valued dests an explicitly-passed CLI list wins over a YAML cohort.

**A wrongly-TYPED YAML value is reported, not swallowed.** Coercion through the
action's own `type=` still keeps the argparse default on failure (one bad key must not
abort a 30-epoch run), but the skip is now recorded with a reason, so it reaches the
stderr report, `WFA2_CONFIG_STRICT=1`, and the config-binding gate. Measured:
`"0.25"` coerces fine; `"nonsense"` and `null` are now visible instead of silent.
