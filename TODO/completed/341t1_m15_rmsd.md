### §3.2 Per-pocket bench aggregation

Each per-pocket record carries:

- `median_best_rmsd_angstrom` (per-pocket median across 3 seeds)
- `mean_best_rmsd_angstrom`, `std_best_rmsd_angstrom`
- `success_rate_at_2_0a`, `success_rate_at_2_5a` (per-pocket success-rate)
- `passes_2_0a_sota`, `passes_2_5a_practical` (SOTA gate verdict)
- `pb_status`, `pb_pass_rate`, `pb_failures` (PoseBusters cross-ref)
- `per_seed_best_rmsd_angstrom` (raw seed-level data)

### §3.3 PoseBusters integration

The adapter follows the **graceful skip** pattern from
`molmetal/validation/posebusters_runner.py`:

- When `posebusters_available()` is True → run the canonical PB check
- When `posebusters_available()` is False → record `SKIPPED` (not fabricating)
- All paths return the same dict schema so downstream consumers see
  a stable contract.

## §5 Constraints & limitations

* **Meeko dependency**: requires meeko 0.8.0 in the project venv
  (verified available 2026-09-29, per Wf-336-X4 §2.1).
* **PoseBusters optional**: package not installed in the project
  venv; PB checks degrade to `SKIPPED` rather than fabricating.
  Per `party-twenty-spirit` §3.5, this is the canonical path —
  do not install posebusters just to make the field non-null.
* **docked_pose_rmsd.json source of truth**: this bench reads
  `metrics/by_metric/docked_pose_rmsd.json` (populated by Wf-179
  BD-9 + Wf-246-B + Wf-247-A).  If the JSON is missing, the per-pocket
  bench returns empty records with `STATUS_SKIPPED` (honest-negative).
* **CPU-only**: the bench does NOT perform docking; it reads the
  pre-computed RMSD data and re-aggregates under the 2.0 Å SOTA gate.
