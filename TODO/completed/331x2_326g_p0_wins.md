## §2 Module architecture

The new module lives at `molmetal/baselines/dmpnn_p0wins.py`.  Each win is
independently importable + testable; there is no monkey-patching of the
original `molmetal/baselines/dmpnn.py`.

### §2.1 Wf-326G-1 — BatchMolGraph flat-tensor forward

* `BatchMolGraph` dataclass mirrors chemprop v2's `BatchMolGraph`
  (`.cloned/chemprop_v2/chemprop/data/collate.py`).
* `batch_mol_graph_from_tuples(graphs)` concatenates every molecule into a
  single flat graph (no padding, no `-1` sentinels).
* `forward_batched_dmpnn(model, bmg)` runs the D rounds of message passing
  ONCE over the whole batch — no Python `for b in range(B)` loop.
* Per-molecule readout via `index_add_` on `atom_batch` (matches
  chemprop v2 `scatter_sum` semantics; uses `index_add_` because the
  buffer is small and `index_add_` is well-supported on CPU/CUDA).
* **CPU bench result (this Wf):** padded path = 2.68 ms/iter, flat path =
  0.95 ms/iter, **2.82× speedup on CPU** for the 4-SMILES smoke batch.
  PROJECTED 5-15× on GPU (per Wf-326G §1.1) — the GPU win comes from
  eliminating the per-mol Python loop's CUDA-stream idle time, which is
  not directly measurable on CPU.

### §2.2 Wf-326G-2 — scatter_reduce_ drop-in

* `scatter_sum_no_self(src, index, dim_size)` returns the same result as
  `torch.zeros(...).index_add_(...)` but uses
  `scatter_reduce_(reduce="sum", include_self=False)` internally.
* The `include_self=False` flag skips the explicit zero buffer init (3×
  memory reduction on the per-call buffer).
* `scatter_sum_no_self_index_add_fallback(...)` provides the reference
  implementation for cross-validation (test #2 verifies equivalence
  across 8 random trials at varying V/E/H).
* **PROJECTED speedup:** 1.2-1.5× + 3× memory reduction on the per-layer
  aggregate step (per Wf-326G §1.2).  Wins scale with the scatter shape:
  the bigger (E, H), the bigger the buffer-save win.

### §2.3 Wf-326G-3 — torch.compile + TF32 + Adam(fused=True)

* `setup_optimized_dmpnn_env(enable_tf32=True)` sets
  `torch.set_float32_matmul_precision("high")` + enables CUDA + cuDNN
  TF32 paths.  Idempotent (re-flipping is a no-op).
* `compile_dmpnn_model(model, mode="default")` wraps `model.forward` in
  `torch.compile`.  Caller is responsible for invoking this AFTER model
  construction + state-dict load (compile signature is captured at first
  forward).
* `make_optimized_adam(params, lr=1e-3, fused=True)` is a drop-in factory
  for `torch.optim.Adam(..., fused=True)`.  On CPU the fused path is a
  no-op (no kernel); on CUDA it collapses 5 per-param kernel launches
  into one.
* **PROJECTED speedups:** `torch.compile` 1.3-1.5× on small MLP heads;
  TF32 1.3-1.8× on every `nn.Linear`; Adam fused 1.1-1.3× on opt step
  (per Wf-326G §3.1, §3.3, §3.4).  All three stack.

### §2.4 Wf-326G-4 — BF16 autocast port

* `bf16_predict(model, bmg, device, use_bf16=True)` wraps the forward in
  `torch.amp.autocast("cuda", dtype=torch.bfloat16)`.  Loss + master
  weights stay in FP32.
* `bf16_train_epoch(model, opt, bmg, y_batch, device, use_bf16=True)` is
  a single-step training primitive that mirrors
  `train_dmpnn_multitask.py:803-855` BF16 pattern.
* Auto-fallback: when `device.type != "cuda"` the autocast is skipped
  (BF16 requires CUDA).  Useful for CPU-only tests.
* **PROJECTED speedup:** 1.5-2.0× on Blackwell sm_120 (per Wf-326G
  §3.5).  The basic path was missing BF16; the multitask variant already
  has it (Wf-326G §3.5 PARTIAL row).

### §2.5 Wf-326G-5 — pre_featurize_dmpnn.py runtime hook

* `PreFeaturizedCache(pre_featurized_dir, domain="metal_cytotox")` loads
  the per-domain `.pt` files written by
  `molmetal/scripts/pre_featurize_dmpnn.py` into an in-memory dict keyed
  by canonical SMILES.
* `cache.featurize(smiles_list)` returns the cached graph tuples for
  hits + a `missing_idx` list for misses.
* `cache.featurize_or_rdkit(smiles_list, rdkit_fallback=True)` splices
  RDKit fallback for misses.
* Eliminates the **double-featurise bug** at `dmpnn.py:701`
  (`predict()` re-runs RDKit on every call).
* **PROJECTED speedup:** 2-3× on `predict()` (per Wf-326G §2.1).

## §5 Honest framing

Per `party-twenty-spirit §3.5`:

1. **All PROJECTED speedups (5-15× flat-tensor, 1.2-1.5× scatter, 1.3-1.8× TF32,
   1.5-2.0× BF16, 2-3× pre-featurize) are conservative PyTorch 2.x release-note
   + chemprop v2 benchmark estimates, not MEASURED on RTX 5090 / RTX PRO 6000.**
   The single MEASURED number in this Wf is the 2.82× CPU speedup on the
   4-SMILES smoke batch (test #7).
2. **GPU verification is deferred per AGENTS.md §5.1** ("kill then adapt"
   directive).  No GPU launches are scheduled in Wf-331-X2; the next
   step would be a GPU bench Wf (e.g., Wf-331-X3) that emits a
   JSON report under `molmetal/reports/wf331x3_gpu_bench/`.
4. **The basic `dmpnn.py` is still unoptimised** — this Wf adds a parallel
   module that callers can opt into.  The original Wf-326G audit guards
   in `test_wf326g_missed_optimizations.py` are still valid (they assert
   the basic path is unoptimised; flipping them would mean a separate
   invasive port that touches `dmpnn.py` directly).
5. **`forward_batched_dmpnn` is NOT a drop-in replacement** for
   `DMPNNModel.forward` (different signature).  It is intended for the
   trainer / pipeline authors to call directly when they want the
   flat-tensor path.
