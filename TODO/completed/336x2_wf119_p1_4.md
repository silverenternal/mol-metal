## §5 Launch wrapper structure (4-ablation × 1-seed × 3-ep smoke)

Per Wf-295D §1 Wave-A contract, the wrapper enumerates 4 ablation
configs on 1 seed for 3 epochs each:

| Ablation | `--chemprop-mode` | `--chemprop-min-epochs` | `--chemprop-lomo-init-scale` |
|---|---|---|---|
| `baseline` | `v3-fallback` | (default 10) | (default 1e-3) |
| `v3_fix_only` | `v3-fix` | (default 10) | (default 1e-3) |
| `min_epochs_only` | `v3-fallback` | 3 (override) | (default 1e-3) |
| `lomo_init_scale_only` | `v3-fallback` | (default 10) | 1e-3 (explicit) |

**Honest framing**: the `min_epochs_only` ablation sets `--chemprop-min-epochs 3`
to match the 3-epoch smoke (otherwise the trainer would refuse to train
when `--epochs 3 < --chemprop-min-epochs 10` per Wf-266 floor).
The other 3 ablations use defaults. The smoke shape is intentionally
small so the 2-hr wall budget holds.

**Wall budget**: 4 ablations × 1 seed × 3 epochs = 12 epochs total
(~10 min per epoch on PRO 6000 cuda:0 per Wf-295D §1 estimate).
Total ~2 hr on PRO 6000 cuda:0.

**Common args** (per Wf-321H + Wf-328):

```bash
--epochs 3
--allow-single-seed  # smoke: 1 seed is honest-negative acceptable
--seeds 0
--batch-size 50
--hidden 300
--depth 3
--lr 1e-3
--device cuda:0
--no-bf16            # Wf-328-W3 BF16 default OFF for chemprop smoke (per Wf-321H §2)
--num-workers 8      # Wf-328-W2 OPTIMAL_NUM_WORKERS on 24-core host
```

**User OK gate** (kill_then_adapt standing directive):
- `--dry-run` → CPU verification only (no GPU work)
- no env var → `ABORTING — no GPU work executed` (rc=1)
- `USER_OK=1` → proceeds with real launch
- `USER_OK=1 SKIP_ABLATIONS=bond,closure` → skip named ablations
